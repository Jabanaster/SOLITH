## Cause of the prior apparent contradiction

`packaged-native-binary-verification.csv` compared the final packaged binary (state 6) against
the STANDALONE Electron-ABI rebuild (state 3) and correctly found no match. `native-binary-
inventory.csv` compared the final packaged binary (state 6) against the vendor-tree build output
AS IT STOOD AT PHASE 9 (state 4) and correctly found a match. States 3 and 4 are two different
files that happened to occupy the same file path (`vendor/memoryjs-3.5.1-patched/build/Release/
memoryjs.node`) at two different times — electron-builder's own `@electron/rebuild` step
overwrote state 3 with state 4 in place, before packaging copied state 4 out to become state 6.
Both original statements were factually correct for their respective comparison pairs; neither
disambiguated which vendor-tree snapshot it meant, which read as a contradiction when the two
files were cross-referenced without the full timeline. Root cause: documentation clarity gap,
not a data or verification defect. See evidence-corrections.md for the full Phase 3 answer set.

## Byte-identity conclusion

packaged binary) are NOT byte-identical. This is expected — two independent `node-gyp`
invocations of identical, unchanged source produce different PE-embedded build metadata.
State 4 and state 6 ARE byte-identical (state 6 is a direct file copy of state 4).

path under the real Electron runtime and exercising both defects against the real Gate 2.2
fixture — not inferred from any hash comparison. This proof stands regardless of which prior
rebuild state 6 does or does not hash-match.
