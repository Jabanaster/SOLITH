## Gate 2.5 findings

The initial live Wisp test found a real security defect: live-memory-freeze-stop and live-memory-freeze-status did not enforce the main-window trusted-sender/window-type guard used by freeze proposal, consent, start, and rollback. A trusted overlay could reach those handlers and receive session-level results. Gate 2.5 added the existing requireTrustedSender(event) guard to exactly those two handlers. No validator, allow-list, consent, process-selection, URL, identity, rollback, or cleanup control was weakened.

Final live packaged results:

- Child frames: complete for same-origin, trusted-looking, untrusted local file, cross-origin local HTTP, and nested frames. No child had an own or parent-accessible preload bridge; the existing not_main_frame guard remains defense in depth.
- Stale/destroyed frames: complete for removal, navigation, parent reload, null/disposed source path, and stale authority revocation.
- DevTools: complete for the strongest genuine supported boundary. A detached real DevTools context had no preload bridge, Node access, or trusted Solith identity. No fabricated sender was used.
- Wisp recreation: complete. The actual overlay was created, destroyed, and recreated through the production toggle. The new webContents identity differed; the old page was unusable; all seven main-only privileged operations rejected before and after recreation.
- Test hooks: 8 inventory rows (7 retained global functions plus the removed freeze-start hook). Absent and nine non-1 variants expose zero hooks; exact 1 exposes seven main-process-only functions; renderer mutation cannot activate the guard.
