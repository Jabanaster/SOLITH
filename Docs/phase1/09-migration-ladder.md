# Phase 1 / Stage 1 — Migration Ladder & Legacy Retirement Plan

## Migration ladder (1.14)

Incremental, evidence-gated — no big-bang replacement. Each increment is independently mergeable, independently testable (doc 08), and leaves the product in a working state (old scanner remains the active path until its replacement is proven at parity). Adjusted from the mission's suggested skeleton based on the actual defect ledger (docs 02/03) and architecture (doc 06/07).

| # | Increment | Scope | Closes / enables |
|---|---|---|---|
| P1.1 | Native scaffold | `napi-rs` crate skeleton (`native/solith-scanner-core`), builds and loads under Electron via `electron-rebuild`, CI build step added, a trivial "ping" export proves the FFI boundary works end-to-end (TS → Rust → TS) before any real logic is written. | Retires nothing yet; de-risks the FFI/build/packaging chain (doc 06 §1.12) before it's load-bearing. |
| P1.2 | Region enumeration | `enumerate_regions()` (doc 06 §2.1) — one canonical allow-list readability policy, `RegionKind` classification. Exposed read-only via a diagnostic IPC channel for manual comparison against today's `getRegions()` output on a real process. | Resolves the deny-list/allow-list divergence (doc 01 §18 #4). No scan logic depends on it yet. |
| P1.3 | Chunked reader | `reader.rs` — chunked reads with type/pattern-width overlap (doc 06 §2.2), structured `ScanError` enum. Unit + property tests (doc 08 A/C) prove no missed cross-chunk value at any boundary. | Structurally retires the 1 MiB cap as a correctness limit (D02) and the cross-region-boundary gap (P1-SCAN-004) — the two most severe defects — before any scan mode is ported. |
| P1.4 | Exact primitive scans | `scan::exact` — EXACT mode (doc 07) across the full i8–u64/f32/f64 type matrix (doc 06 §2.4), default unaligned-safe. Wired behind a feature flag so it can run **side-by-side** with the existing TypeScript `scanFirst` for A/B parity comparison on real fixtures (doc 08 B) before becoming the default path. | Closes B's absence (confirmed-absent, carried forward as a strengthened guarantee) and the narrower-type-matrix gap (doc 05). |
| P1.5 | 64-bit-safe result model | BigInt end-to-end for both addresses and int64/uint64 *values* (doc 06 §1.8) — the IPC payload shape change (doc 06's flagged breaking `ScanMatch.value: number \| bigint`) lands here, together with its own migration of every IPC serializer/consumer in one atomic increment (never a partial rollout where some consumers expect `number` and others `bigint`). | Closes D06 (int64 precision loss + collision). |
| P1.6 | Refinement engine | `scan::refine` — CHANGED/UNCHANGED/INCREASED/DECREASED/INCREASED_BY/DECREASED_BY (doc 07), including the magnitude-aware epsilon replacement for `DELTA_EPSILON` and the explicit (not accidental) finite-value gate applied uniformly across every comparator. | Closes P1-SCAN-002 (asymmetric NaN guard) and P1-SCAN-003 (fixed epsilon). |
| P1.7 | Unknown-initial / comparative modes | `scan::unknown` — baseline capture with Rust-owned storage (doc 06 §1.9/§3, no JS-heap copy), narrowing via the refinement engine from P1.6. | Removes the `unknownSnapshots` JS-heap-copy design entirely, structurally closing P1-SCAN-006 (no cap needed once the storage model itself changes) rather than patching the old Map with a cap/TTL. |
| P1.8 | Strings/byte arrays | UTF-8/UTF-16 string scan, fixed-length byte-array scan — genuinely new capability (doc 05: "absent" today), built on the same chunked reader from P1.3. | Closes the CE-gap-matrix string-scan row. |
| P1.9 | AOB engine | `aob::` — single canonical native exact-match engine (doc 06 §5), replacing `aob-resolver.ts` and `signature-engine.ts`'s exact-match path; `signature-engine.ts`'s fuzzy/drift matching is *kept* in TypeScript, re-pointed to call the new native primitive for its inner exact-match step (not ported). | Closes D04 (AOB false negative/no-truncation-signal) and, via P1.3's chunked reader, the AOB-specific instance of P1-SCAN-004. |
| P1.10 | Cancellation/progress/completeness | Cancellation token (doc 06 §1.5) and progress callback (doc 06 §1.6) wired through every mode from P1.4–P1.9; the full `ScanCompleteness` enum (doc 06 §4) replaces the boolean `truncated` on every result type, including AOB's previously-nonexistent one. Async worker-pool execution (doc 06 §1.4) replaces the current fully-synchronous scan loop. | Closes D01 (all 5 untouched siblings) and D05 (pointer-scan truncation misreporting — see P1.11) at the architectural root, plus P1-SCAN-005 (main-thread-blocking synchronous scans) and P1-SCAN-008 (batched/paginated IPC delivery lands here alongside the progress-event channel). |
| P1.11 | Pointer scanner | `pointer::` — BFS pointer-chain scan (doc 06 §1), ported onto the new chunked reader/completeness model, with the `MAX_RESULTS`-cap-without-`truncated`-flag bug (D05) fixed as part of the port (not carried forward), and explicit 32-bit/64-bit pointer-width handling per the target process's actual bitness (closes P1-SCAN-001 — bitness detection is added here, at the one place it matters). | Closes D05 and P1-SCAN-001. |
| P1.12 | TS/Electron integration | `LiveMemorySession`/`MemoryManager` re-pointed from `memory-scanner.ts`/`pointer-scanner.ts`/`aob-resolver.ts` to the new native core via a thin adapter layer; all policy logic (attach authorization, online-guard, protected-target, write-consent/propose/confirm/rollback, freeze) stays in TypeScript, unmodified in behavior (per doc 06 §1's scope boundary). `FakeMemoryDriver` is upgraded per P1-SCAN-010's fix (doc 08 D) in the same increment, not after. | Closes P1-SCAN-010 (fake-vs-production divergence) and — as a byproduct of the propose/confirm code being touched during adapter wiring — is the natural point to also fix P1-SCAN-007 (`confirmWrite` TOCTOU), evaluated and fixed here since it is a TypeScript-layer defect unrelated to the native core itself but discovered during this Stage 1 pass. |
| P1.13 | Old-scanner parity suite | Full doc-08 test suite (A–D) re-run against the new native core; every one of the 16 defect IDs (D01–D06, P1-SCAN-001–010) has a passing regression test; the side-by-side A/B comparison from P1.4 is finalized with the old TypeScript scanner still present but no longer the default. | Verification gate before real-game validation. |
| P1.14 | Real-game certification | Doc 08 layer E — Stardew Valley + Palworld, full-coverage proof, doc-04-comparable before/after performance numbers. | Required before Phase 1 can close (mission's explicit instruction). |
| P1.15 | Legacy scanner retirement | See disposition table below — `memory-scanner.ts`, `pointer-scanner.ts`, `aob-resolver.ts`'s exact-match path are deleted (or reduced to an explicitly-approved compatibility shim, if a caller outside the migrated set is found during P1.12 that cannot yet be re-pointed); `native-memory-driver.ts` is retained (still the real memoryjs boundary for any code path Phase 1 does not migrate — see disposition table) unless Phase 1's own scope is later extended to fully replace it. | Final step — no two independent production scanners left drifting, per the mission's explicit prohibition. |

## Legacy retirement plan (1.15)

Disposition for every file identified in doc 01's inventory, using the mission's six-state vocabulary:

| File | Disposition | Rationale |
|---|---|---|
| `src/core/live-memory/memory-scanner.ts` | **DELETE_AFTER_PARITY** (at P1.15) | Fully replaced by the native core's `scan::*` modules (P1.4–P1.8); kept side-by-side only through P1.13's A/B parity verification. |
| `src/core/live-memory/pointer-scanner.ts` | **DELETE_AFTER_PARITY** (at P1.15) | Fully replaced by `pointer::` (P1.11). |
| `src/core/live-memory/aob-resolver.ts` | **DELETE_AFTER_PARITY** (at P1.15) | Fully replaced by `aob::` (P1.9). |
| `src/core/live-memory/signature-engine.ts` | **REFACTOR** | Fuzzy/drift-matching logic (Hamming/edit-distance, `hintAddress`-scoped search) is *kept*, re-pointed to call the new native exact-match primitive for its inner search step (doc 06 §5) instead of `aob-resolver.ts`'s TypeScript implementation. Not deleted, not left unchanged. |
| `src/core/live-memory/native-memory-driver.ts` | **KEEP** (scope-limited) | Remains the real `memoryjs` boundary for any live-memory code path Phase 1 does not migrate (e.g. `readMemory`/`writeMemory` single-value calls used by `RealtimeScanner`/rollback, which are out of Phase 1's scanning-specific scope). Its 1 MiB cap becomes irrelevant to *scanning* once P1.3 lands, but the driver itself is not retired — narrowing its remaining responsibility, not removing it, is the correct disposition here. |
| `src/core/live-memory/real-time-scanner.ts` | **KEEP**, revisit in a later phase | Its polling design (re-read known addresses) is orthogonal to the first-scan/refinement engine Phase 1 targets; not blocking Phase 1 exit. Flagged for a future phase to evaluate migrating its per-address reads onto the native `readMemory` path once P1.12's adapter layer exists, purely as a consistency improvement, not a defect fix. |
| `src/core/live-memory/live-memory-session.ts` | **REFACTOR** | Attach/policy/consent/propose/confirm/rollback/freeze orchestration is kept and unmodified in *behavior*; its scan-method bodies (`scanFirst`, `scanFirstAutoMatrix`, `scanNext`, `scanFirstUnknown`, `scanNextFromUnknown`, `pointerScan`) are rewritten as thin adapters calling the native core (P1.12). The `confirmWrite` TOCTOU fix (P1-SCAN-007) lands here too. |
| `src/core/live-memory/memory-manager.ts` | **KEEP** | Write-policy-gated orchestration, unaffected by the scanning-engine swap. |
| `src/core/live-memory/types.ts` | **REFACTOR** | `LiveValueType` gains the full i8–u64 matrix + string/bytes (doc 06 §2.4); `ScanMatch.value` gains the `number \| bigint` union (P1.5); `MemoryDriver` interface gains a `completeness`-aware return-shape option or a parallel v2 interface, decided during Stage 2 implementation planning (not a Stage 1 decision to force now). |
| `electron/live-memory-ipc.ts` | **REFACTOR** | New `live-memory-scan-cancel`/`live-memory-scan-progress` channels added (additive); existing scan-result channels' response shape gains `completeness` (breaking, versioned/migrated in one atomic increment per P1.5/P1.10, never a mixed rollout). |
| `electron/preload.ts`, `electron/ipc-validation.ts` | **REFACTOR** | Extended in lockstep with the IPC channel changes above; no structural redesign needed. |
| `tests/fixtures/fake-memory-driver.ts` | **REFACTOR** | Upgraded to enforce the real driver's constraints (P1-SCAN-010 fix) — 1 MiB cap, address-range validation, finite-value-on-write validation, PID upper-bound check — in the same increment as P1.12, not deferred. |
| `tests/live-memory/memory-scanner.test.ts`, `pointer-scanner.test.ts`, `aob-resolver.test.ts`, `signature-engine.test.ts` | **TEST_ONLY**, then superseded | Kept passing against the old implementation through P1.13's parity gate (never weakened/skipped in the interim, per doc 08's coverage-preservation discipline); superseded by the new native-core test suite (doc 08 A/B/C/D) once P1.15 deletes the old implementation, at which point these specific test files are deleted alongside the source they tested (a test file testing deleted code is dead weight, not a compatibility shim). |
| `src/core/runtime/*` (the separate headless/verification stack) | **KEEP**, out of scope | Structurally independent of the interactive scanner (doc 01 §0); not touched by Phase 1. Its own `signature-scanner.ts` (chunked, cancellable, honest-truncation) is cited in doc 06 as the *existing in-repo precedent* the new native core's design borrows from — an architectural reference, not code to migrate. |
| `native/solith-readonly-scanner/` (Rust binary) | **KEEP**, out of scope | Separate, already-certified read-only pointer-chain validation tool; not replaced or merged into the new crate (doc 06 §1.3's explicit "one crate, not several" decision is about the *new* scanner core, not about consolidating with this pre-existing, differently-scoped binary). |
| `vendor/memoryjs-3.5.1-patched/` | **KEEP**, scope-narrowed | Remains in the tree as long as `native-memory-driver.ts` (KEEP, scope-limited, above) still depends on it for non-scanning live-memory operations. Not a **COMPATIBILITY_SHIM** in the formal sense (it's not standing in for removed functionality) — it retains its own, narrower, real responsibility. |
| `src/core/in-process-script/native-bridge.ts` | **KEEP**, out of scope | Code-cave injection feature, unrelated to scanning; untouched by Phase 1. |

**Retirement point, explicitly stated**: the old TypeScript scanner (`memory-scanner.ts`, `pointer-scanner.ts`, `aob-resolver.ts`'s exact-match path) becomes removable **only after P1.13's parity suite is green and P1.14's real-game certification (Stardew Valley + Palworld) has passed against the new native core** — not before, and not on a "the new code looks right" basis. Until that point, both implementations may coexist behind a feature flag (P1.4's side-by-side A/B design), but the native core is never the *only* certified path until parity is proven, and the old path is never left running in production after parity *is* proven (no indefinite dual-maintenance).

**Legacy retirement plan complete: YES.**
