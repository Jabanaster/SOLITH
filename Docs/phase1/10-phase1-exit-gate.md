## Explicit non-requirements (do not block Phase 1 exit)

Per the mission's own scope notes and doc 09's disposition table, the following are **not** exit-gate blockers, to prevent scope creep from silently expanding Phase 1:

- Full 32-bit/WOW64 fixture-based proof for P1-SCAN-001, **if** genuinely infeasible to construct within Stage 2's timeline — must instead be closed by the pointer-scanner's explicit bitness-detection code (P1.11) plus a documented, owner-acknowledged gap in real-fixture coverage, never silently dropped from the ledger.
- Saved/persisted scan sessions across app restarts (doc 05's CE-gap row explicitly marks this evaluate-later, not required).
- A bitmap/compressed candidate-set storage optimization for post-narrowing candidate lists (doc 06 §3 explicitly defers this as a future optimization, not a Phase 1 blocker, since doc 04's baseline shows region-read count, not candidate-list memory, is the dominant cost).
- Vectorscan-backed batch AOB matching for CT-corpus-scale validation workloads (doc 06 §5 — a separate, later-phase concern, explicitly not required for the interactive scanner's Phase 1 exit).
- `real-time-scanner.ts`'s migration onto the native `readMemory` path (doc 09 — flagged for a later phase as a consistency improvement, not a Phase 1 defect fix).

**Phase 1 exit gate design: complete YES.**
