## REUSE/EXTEND/ADAPT/SUPERSEDE/NOT_RELEVANT classification (mission §3)

- **REUSE**: `MemoryDriver.getRegions()`/`readBuffer()` (region profile measurement and the adaptive scan loop's own reads); `ScanCoverageTracker`/`selectScannableRegions` (exported, unmodified logic, reused verbatim for eligibility+coverage bookkeeping); `encodeValue`/`valueSize` (exported, unmodified value encoding); the `operationId`/`AbortController`/`scanOperations` cancellation convention (`startExactScanOperation`/pointer-map scans); the `structureSnapshots` FIFO-eviction style for bounded history; the existing `p2-*-real-process.e2e.test.ts`/packaged pairing and `spawnFixture`/`writeBytes` stdin-protocol test conventions.
- **EXTEND**: `ScanBounds` (new optional `regionOrder` field — additive, default-preserving); `selectScannableRegions` (new optional sort step, applied only when `regionOrder` is supplied); `LiveMemorySession` (new `adaptiveScanTelemetry` field + 2 new methods); `electron/live-memory-ipc.ts`/`preload.ts`/`global.d.ts` (2 new channels, reusing existing cancel/poll); `LiveMemoryTrainerPage.tsx` (new mounted panel, no restructuring of the existing page).
- **ADAPT**: none required — no existing vocabulary needed reinterpreting for this mission.
- **SUPERSEDE**: none — no competing or wrong-direction planner-like code existed to replace.
- **NOT_RELEVANT**: `ScannerBackendRouter`/`NativeScannerBackend` (the dual-backend contract) was evaluated and deliberately **not** used as the planner's execution seam — only exact/AOB scans are routed through it today, and it has no per-region-order hook; building on the lower-level `MemoryDriver` primitive directly (same primitive `memory-scanner.ts` itself uses) kept the change additive and low-risk instead of extending a contract mid-migration. This is a documented design choice, not an oversight.

## Known gaps (disclosed, not fabricated)

1. **Real-game proof (§24) not completed.** Two installed, ROADMAP-preferred titles (Godlike Burger, DREDGE) both failed to launch in this automated session despite a confirmed, already-logged-in Steam client — the game process exits within seconds with no window and no diagnosable error in Steam's own logs. This looks like an environment characteristic of this specific sandboxed session (no interactive desktop/session-0 state a Steam game launch typically needs), not a planner defect, but it was **not** proven, only inferred, and is reported honestly as NOT_COMPLETED rather than skipped silently or faked.
2. **Cancellation (§17) UI/mid-scan proof stays at engine level.** The orchestration layer's genuine per-region cancellation is unit-tested directly (`adaptive-scan-orchestration.test.ts`); it was not additionally re-proven through the real-process fixture suite or the UI e2e suite this pass, to keep the mission's already-large scope bounded. The mechanism is identical in the UI (same `operationId`/cancel channel every other cancellable scan uses), so this is judged a reasonable, disclosed scope cut rather than an unproven gap.
3. **Failure injection (§29) partial.** Forced-fallback (stale/corrupt telemetry) is unit-tested. No-regions, all-unreadable, and telemetry-absent-after-restart scenarios were not separately fixture-proven this pass — they are structurally covered by the same `ScanCoverageTracker`/`selectScannableRegions` code paths the rest of the scanner suite already exercises (an empty-regions enumeration, for example, is exactly the pre-existing "process exited" detection those 500+ tests already certify), but that is inherited coverage, not a P2-10-specific fixture proof.
